## 1. What Motion Canvas actually is

Motion Canvas has **two parts**:

- **TypeScript animation library:** describes what is on screen and how it changes.
- **Browser editor:** previews the animation, lets you scrub the timeline, adjust events, and render/export.

An animation is a **project** containing one or more **scenes**. A scene contains a tree of **nodes** (rectangles, circles, text, lines, images, etc.). Each node has **signals**, such as `x`, `fill`, `opacity`, `scale`, and `rotation`. You use **generator functions** to animate those signals over time.

```text
Project
  ├── Scene A (generator)
  │     └── View
  │           ├── Rect
  │           │     └── Txt
  │           ├── Line
  │           └── Circle
  └── Scene B (generator)
        └── View
              └── ...
```

**Important:** Motion Canvas **uses JSX but is not React**. Its `<Rect />` and `<Txt />` elements directly instantiate scene nodes. There is no React DOM or React state lifecycle.

### A useful mental translation

| What you want | Motion Canvas concept |
|---|---|
| Draw a box | `<Rect />` |
| Show a label | `<Txt />` |
| Draw a message arrow | `<Line endArrow />` |
| Move a box | `yield* box().x(300, 1)` |
| Fade in a label | `yield* label().opacity(1, 0.4)` |
| Animate two things at once | `yield* all(a(), b())` |
| Pause for a second | `yield* waitFor(1)` |
| Make a value change reactively | `createSignal(...)` or a node signal |
| Reuse an animation | `function* ...(): ThreadGenerator` |
| Synchronize to a voiceover | `waitUntil('event-name')` |

## 2. Install and run

### Prerequisites

- Node.js and npm (use a current supported Node.js LTS release).
- An editor with TypeScript/TSX support.

### Create a project

```bash
npm init @motion-canvas@latest
```

In the interactive setup, choose **TypeScript** and a project directory. Choose the **Video (FFmpeg)** exporter if you want MP4; the image-sequence exporter is useful for sequences of PNG frames.

Then, from the created directory:

```bash
cd YOUR_PROJECT_DIRECTORY
npm install
npm start
```

Open **http://localhost:9000/** (or the address printed in your terminal).

> **If your generated project uses a different script**, check `package.json` and run that script. Older guides may say `npm run serve`; the current official quickstart uses `npm start`.

**Source:** [Official quickstart](https://motion-canvas.io/docs/quickstart/).

## 3. Understand the project files

A typical generated project contains the files below (the scaffold may contain extra files or slightly different names):

```text
my-animation/
├── package.json
├── vite.config.ts
└── src/
    ├── project.ts
    └── scenes/
        └── example.tsx
```

### `src/project.ts`: what scenes play?

```ts
import {makeProject} from '@motion-canvas/core';
import example from './scenes/example?scene';

export default makeProject({
  scenes: [example],
});
```

**The `?scene` suffix matters.** It is consumed by Motion Canvas's Vite integration. Leaving it out can break editor scene loading and hot reloading.

### `vite.config.ts`: how the editor/build runs

An example minimal configuration:

```ts
import {defineConfig} from 'vite';
import motionCanvas from '@motion-canvas/vite-plugin';

export default defineConfig({
  plugins: [motionCanvas()],
});
```

Your generated Vite file may also include `ffmpeg()` or other exporters. **Keep the scaffold's existing exporter configuration.**

### `src/scenes/example.tsx`: what happens on screen?

```tsx
import {makeScene2D} from '@motion-canvas/2d';

export default makeScene2D(function* (view) {
  // Add nodes to `view`.
  // Use yield* to animate them.
});
```

The `view` is the scene's root node. Everything visible is ultimately attached to it.

## 4. Your first complete animation

**Copy the whole snippet below** into `src/scenes/example.tsx`. This is a complete scene, not a partial excerpt.

```tsx
import {Circle, makeScene2D, Txt} from '@motion-canvas/2d';
import {all, createRef, waitFor} from '@motion-canvas/core';

export default makeScene2D(function* (view) {
  view.fill('#101827');

  const circle = createRef<Circle>();
  const label = createRef<Txt>();

  view.add(
    <>
      <Circle
        ref={circle}
        x={-350}
        y={20}
        size={160}
        fill={'#38bdf8'}
      />
      <Txt
        ref={label}
        text={'A workflow begins'}
        y={-170}
        fill={'#f8fafc'}
        fontSize={48}
        opacity={0}
      />
    </>,
  );

  // Phase 1: reveal the text.
  yield* label().opacity(1, 0.6);

  // Phase 2: move and recolor the circle at the same time.
  yield* all(
    circle().x(350, 2),
    circle().fill('#34d399', 2),
    circle().rotation(180, 2),
  );

  // Phase 3: pause, then change the text.
  yield* waitFor(0.5);
  yield* label().text('Activity completed', 0.7);

  // Phase 4: restore the circle.
  yield* all(
    circle().x(0, 0.7),
    circle().scale(0.7, 0.7),
  );

  yield* waitFor(0.6);
});
```

### Read this scene in plain English

1. Set a dark background.
2. Create references to a circle and a label.
3. Add them to the scene at their initial positions.
4. Fade the label in.
5. Move, recolor, and rotate the circle **in parallel**.
6. Pause, replace the label, then move and shrink the circle.

There is no manual frame-by-frame calculation. Motion Canvas generates the intermediate frames for you.

## 5. The six concepts you must understand

### 5.1 Nodes: actual things in the scene

`Circle`, `Rect`, `Txt`, `Line`, `Layout`, and `Camera` are nodes. Parent nodes can contain children, and child transforms are relative to their parents.

```tsx
view.add(
  <Rect width={400} height={180} fill={'#1e293b'} radius={20}>
    <Txt text={'Temporal Server'} fill={'white'} fontSize={38} />
  </Rect>,
);
```

### 5.2 References: how you access a node later

```tsx
const serverBox = createRef<Rect>();

view.add(
  <Rect ref={serverBox} width={400} height={160} fill={'#334155'} />,
);

// `serverBox` is a reference accessor. Call it to get the node.
yield* serverBox().scale(1.2, 0.5);
```

**Critical detail:** `serverBox()` works only **after** the node has been created/added. Do not access a reference before `view.add(...)` initializes it.

### 5.3 Signals: readable, writable, animatable properties

The same `x` signal supports three modes:

```ts
const currentX = serverBox().x(); // Read the number.
serverBox().x(120);               // Set immediately.
yield* serverBox().x(300, 1);     // Animate to 300 over 1 second.
```

That third call returns a tween generator; `yield*` runs it.

### 5.4 Generators: why we write `function*` and `yield*`

```ts
// Conceptual generator, independent of Motion Canvas:
function* demonstrate() {
  yield 1;
  yield 2;
}
```

In Motion Canvas, a scene is a generator function. **`yield*` delegates to an animation generator and waits for its completion**:

```ts
yield* serverBox().x(300, 1);
yield* serverBox().opacity(0, 0.5);
```

Here, fade-out starts **after** movement ends.

Do not confuse this with `async`/`await` or a real background job. Generators define a timeline under the Motion Canvas playback engine.

### 5.5 Scene hierarchy: parenting changes coordinates

```tsx
view.add(
  <Rect x={200} y={0} size={240} fill={'#334155'}>
    <Circle x={80} y={0} size={40} fill={'#38bdf8'} />
  </Rect>,
);
```

The circle is offset **80 pixels relative to the rectangle**, not relative to the whole scene.

### 5.6 Every animation has a duration

```ts
yield* serverBox().rotation(90, 0.6);
```

This turns the node to **90 degrees** over **0.6 seconds**. `rotation` is a target value, not “rotate by 90 more degrees.” If it was already at 90, targeting 90 again will not add another turn.

## 6. Shapes, text, and drawing arrows

### Basic shapes

**Snippet to place inside an existing scene's `view.add(...)`:**

```tsx
view.add(
  <>
    <Rect
      x={-320}
      width={220}
      height={120}
      radius={16}
      fill={'#2563eb'}
    />
    <Circle x={0} size={120} fill={'#10b981'} />
    <Txt
      x={320}
      text={'Task Queue'}
      fontSize={38}
      fill={'#f8fafc'}
    />
  </>,
);
```

### Draw an arrow over time

This is a **complete scene** that draws an arrow from a worker to a server.

```tsx
import {Line, makeScene2D, Txt} from '@motion-canvas/2d';
import {all, createRef, waitFor} from '@motion-canvas/core';

export default makeScene2D(function* (view) {
  view.fill('#0f172a');

  const arrow = createRef<Line>();
  const label = createRef<Txt>();

  view.add(
    <>
      <Line
        ref={arrow}
        points={[[-450, 0], [450, 0]]}
        stroke={'#38bdf8'}
        lineWidth={7}
        endArrow
        arrowSize={22}
        end={0}
      />
      <Txt
        ref={label}
        text={'ScheduleActivityTask'}
        fontSize={38}
        fill={'#f8fafc'}
        y={-70}
        opacity={0}
      />
    </>,
  );

  yield* all(
    arrow().end(1, 1.2),
    label().opacity(1, 0.5),
  );
  yield* waitFor(0.5);
});
```

**Key detail:** `Line.end` ranges from `0` to `1`: `0` shows none of the line, `1` shows the entire line. That makes it perfect for drawing message arrows progressively. `endArrow` adds an arrowhead at the visible end. Use `startArrow` if you need the opposite end.

### Dashed lifelines (sequence diagrams)

```tsx
view.add(
  <Line
    points={[[0, -280], [0, 360]]}
    stroke={'#64748b'}
    lineWidth={3}
    lineDash={[10, 12]}
    opacity={0.65}
  />,
);
```

### Fade, scale, rotate, and change stroke

```ts
// `box` and `arrow` are initialized createRef(...) references.
yield* box().opacity(0.3, 0.3);
yield* box().scale(1.4, 0.5);
yield* box().rotation(20, 0.5);
yield* arrow().stroke('#f59e0b', 0.4);
```

For sequence diagrams, prefer simple arrows and opacity highlights over spectacular effects. The job is **clarity**.

**Source:** [Line API](https://motion-canvas.io/api/2d/components/Line/).

## 7. Sequencing and timing

**These snippets belong inside a scene after the referenced nodes have been added.**

### Sequential: one after another

```ts
yield* worker().opacity(1, 0.5);
yield* worker().x(250, 1);
yield* waitFor(0.4);
```

### Parallel: start together, wait for all

```tsx
import {all} from '@motion-canvas/core';

// Inside the scene:
yield* all(
  worker().x(250, 1),
  worker().fill('#22c55e', 1),
  label().opacity(1, 0.4),
);
```

### Staggered: start sequentially, but overlap

```tsx
import {sequence} from '@motion-canvas/core';

// Inside the scene:
yield* sequence(
  0.25,  // delay between animation starts (seconds)
  first().opacity(1, 0.8),
  second().opacity(1, 0.8),
  third().opacity(1, 0.8),
);
```

**Important:** `sequence(0.25, ...)` does **not** mean “wait until each animation finishes.” It starts the next animation 0.25 seconds later, potentially **overlapping** the previous one. For strict sequential behavior, use consecutive `yield*` calls or `chain(...)`.

### Chain tweens on the same property

```ts
yield* worker()
  .x(250, 1)
  .to(-250, 1)
  .to(0, 0.6);
```

### Delay one action while another begins

```tsx
import {all, delay} from '@motion-canvas/core';

// Inside the scene:
yield* all(
  worker().x(300, 1.5),
  delay(0.5, label().opacity(1, 0.4)),
);
```

### Easing

The simplest signal tweens have built-in interpolation. You can pass easing functions when the API supports them, for example:

```tsx
import {easeInOutCubic} from '@motion-canvas/core';

// Inside the scene:
yield* worker().x(300, 1.2, easeInOutCubic);
```

Use **steady motion** for messages moving between participants; use gentle easing for panels appearing and changing focus. Abrupt easing can make architectural flows harder to track.

**Source:** [Animation flow](https://motion-canvas.io/docs/flow/) and [Tweening](https://motion-canvas.io/docs/tweening/).

## 8. Signals and automatic relationships

A signal isn't merely a variable. A signal can be **reactively derived from another signal**.

### Derived status label: complete scene

```tsx
import {makeScene2D, Txt} from '@motion-canvas/2d';
import {createSignal, waitFor} from '@motion-canvas/core';

export default makeScene2D(function* (view) {
  view.fill('#0f172a');

  const batchSize = createSignal(0);

  view.add(
    <Txt
      text={() => `Pending servers: ${batchSize()}`}
      fill={'#f8fafc'}
      fontSize={52}
    />,
  );

  yield* batchSize(5, 1);
  yield* waitFor(0.4);
  yield* batchSize(20, 1.5);
  yield* waitFor(0.4);
});
```

As `batchSize` changes, the `Txt` node updates automatically. No manual text-update loop is needed.

### When should you use signals?

- A box follows a moving participant.
- The current batch count changes over time.
- The color of a status badge derives from completion state.
- Multiple labels reflect one shared value.

### When should you *not* use an effect?

For derived visual properties, prefer a signal dependency. `createEffect` and `createDeferredEffect` are for side effects, such as modifying scene hierarchy in response to changing signals. In most beginner diagrams, you don't need effects at all.

**Source:** [Signals](https://motion-canvas.io/docs/signals/) and [Effects](https://motion-canvas.io/docs/effects/).

## 9. Layouts and coordinate systems

### Coordinates: center origin

In a typical scene:

```text
                 y = negative (up)
                       ↑
     x = negative  ← (0,0) → x = positive
                       ↓
                 y = positive (down)
```

The center of the canvas is `(0, 0)`, not the top-left corner. Nodes are positioned relative to their parents, and `y` increases **downward**.

### Use coordinates for sequence diagrams

For lifelines, predictable absolute X positions are excellent:

```ts
const laneX = {
  client: -650,
  server: -200,
  workflowWorker: 250,
  activityWorker: 700,
};
```

### Use layout when you want automatically arranged cards

```tsx
import {Layout, Rect, Txt} from '@motion-canvas/2d';

// Inside a scene:
view.add(
  <Layout layout direction={'row'} gap={28} alignItems={'center'}>
    <Rect width={220} height={100} fill={'#1d4ed8'} radius={12}>
      <Txt text={'API'} fill={'white'} fontSize={30} />
    </Rect>
    <Rect width={220} height={100} fill={'#475569'} radius={12}>
      <Txt text={'Temporal'} fill={'white'} fontSize={30} />
    </Rect>
  </Layout>,
);
```

Motion Canvas's layout system is **opt-in**. Setting `layout` enables its Flexbox-like behavior. It is not browser CSS, even though the terminology is familiar.

### Practical rule

- Use explicit X/Y coordinates for **sequence diagram lanes and message positions**.
- Use `<Layout layout ...>` for **headers, cards, legends, and dashboard sections**.
- Avoid changing participant X positions in the middle of a sequence animation; doing so makes messages harder to follow.

**Source:** [Positioning](https://motion-canvas.io/docs/positioning/) and [Layouts](https://motion-canvas.io/docs/layouts/).

## 10. Reusable animations and components

A good motion-graphics project should read like a **story script**, not like hundreds of low-level drawing commands.

### Reusable animation function

**Inside a scene file (after imports):**

```tsx
import {Rect} from '@motion-canvas/2d';
import {all, ThreadGenerator} from '@motion-canvas/core';

function* pulse(node: Rect): ThreadGenerator {
  yield* all(
    node.scale(1.1, 0.3),
    node.opacity(0.75, 0.3),
  );
  yield* all(
    node.scale(1, 0.3),
    node.opacity(1, 0.3),
  );
}

// Inside makeScene2D(...), after creating a reference:
// yield* pulse(serverBox());
```

### Reusable visual component

Simple components can be **functions that return Motion Canvas JSX**. You do not need to implement a custom decorated class for every reusable box.

```tsx
import {Rect, Txt} from '@motion-canvas/2d';

function ParticipantCard(props: {title: string; color: string}) {
  return (
    <Rect
      width={270}
      height={90}
      radius={14}
      fill={props.color}
    >
      <Txt text={props.title} fill={'white'} fontSize={34} />
    </Rect>
  );
}

// Inside a scene:
// view.add(<ParticipantCard title="Temporal Server" color="#1d4ed8" />);
```

For complex custom components with new animatable public properties, Motion Canvas also supports class-based components, signals, and decorators. Start with JSX functions and generator helpers first; only introduce custom classes when they simplify repeated behavior.

**Source:** [References](https://motion-canvas.io/docs/references/) and [Custom components](https://motion-canvas.io/docs/custom-components/).

## 11. Code snippets, camera, scenes, and audio

### Animated code snippets (`Code`, not the deprecated `CodeBlock`)

The `Code` node can show code and animate changes. For syntax highlighting, install the grammar you need:

```bash
npm install @lezer/javascript
```

In **`src/project.ts`**, configure the default highlighter before exporting the project:

```ts
import {makeProject} from '@motion-canvas/core';
import {Code, LezerHighlighter} from '@motion-canvas/2d';
import {parser} from '@lezer/javascript';
import example from './scenes/example?scene';

Code.defaultHighlighter = new LezerHighlighter(
  parser.configure({dialect: 'jsx ts'}),
);

export default makeProject({
  scenes: [example],
});
```

Then **inside a scene**:

```tsx
const code = createRef<Code>();

view.add(
  <Code
    ref={code}
    code={'const status = "Scheduled";'}
    fontSize={40}
  />,
);

yield* code().code('const status = "Completed";', 1);
```

The preceding snippet expects `Code` to be imported from `@motion-canvas/2d` and `createRef` from `@motion-canvas/core` in the scene file.

> **Avoid `CodeBlock`:** the official docs mark it deprecated and recommend `Code` instead.

**Source:** [Code component guide](https://motion-canvas.io/docs/code/).

### Camera: focus on the active part of a diagram

For very large workflow diagrams, a camera helps you zoom into a server or coordinator without moving every element manually.

```tsx
import {Camera, makeScene2D, Rect} from '@motion-canvas/2d';
import {createRef, waitFor} from '@motion-canvas/core';

export default makeScene2D(function* (view) {
  const camera = createRef<Camera>();
  const server = createRef<Rect>();

  view.add(
    <Camera ref={camera}>
      <Rect
        ref={server}
        width={240}
        height={120}
        x={300}
        fill={'#2563eb'}
      />
    </Camera>,
  );

  yield* camera().centerOn(server(), 1);
  yield* camera().zoom(1.7, 1);
  yield* waitFor(0.4);
  yield* camera().reset(1);
});
```

**Tip:** Change camera zoom with `.zoom(...)`, not by directly manipulating camera scale.

**Source:** [Camera](https://motion-canvas.io/docs/camera/).

### Scenes and transitions

Add scenes to the project in the order they should play:

```ts
import {makeProject} from '@motion-canvas/core';
import overview from './scenes/overview?scene';
import workflowTasks from './scenes/workflow-tasks?scene';
import activities from './scenes/activities?scene';

export default makeProject({
  scenes: [overview, workflowTasks, activities],
});
```

In the **beginning of the second scene** (after adding its nodes), you can start with a transition:

```tsx
import {Direction, slideTransition} from '@motion-canvas/core';

// Inside a scene, after `view.add(...)`:
yield* slideTransition(Direction.Left);
```

**Source:** [Scene transitions](https://motion-canvas.io/docs/transitions/).

### Time events: the secret to voiceover synchronization

Instead of hardcoding a long silence, give it a name:

```tsx
import {waitUntil} from '@motion-canvas/core';

// Inside a scene:
yield* waitUntil('explain-task-queue');
// Then animate the queue.
```

The event appears in the editor, where you can adjust timing while listening to your voiceover. The editor also has a presentation mode. You can mark slide boundaries like this:

```tsx
import {beginSlide} from '@motion-canvas/core';

// Inside a scene:
yield* beginSlide('workflow-started');
```

Use **time events** for narrated videos, and **slides** for presenter-controlled explanations.

**Sources:** [Time Events](https://motion-canvas.io/docs/time-events/) and [Presentation](https://motion-canvas.io/docs/presentation/).

## 12. Complete example: Temporal execution sequence diagram

This example is intentionally **one self-contained scene**. It draws four lifelines, animates RPC/message arrows, and updates a bottom caption with the meaning of each step. It is designed to be easy to copy, run, and extend.

### What it explains

```text
Caller          Temporal Server     Workflow Worker      Activity Worker
  |                   |                   |                    |
  |--- Start -------->|                   |                    |
  |                   |<--- Poll WFT -----|                    |
  |                   |--- WFT --------->|                    |
  |                   |<-- Schedule -----|                    |
  |                   |                   |                    |
  |                   |<---------------------- Poll Activity ---|
  |                   |---------------------- Activity Task -->|
  |                   |<---------------------- Complete --------|
  |                   |--- next WFT ---->|                    |
  |                   |<-- Complete -----|                    |
```

**Important accuracy notes:** Workers **long-poll the Temporal Server** for tasks. The arrows labeled “task” represent the server's response to a poll, not an unsolicited server push. Workflow history and task queues are intentionally abstracted into the captions here; they are not modeled as separate network endpoints. A workflow worker determines the next command by executing or replaying workflow code against history; the server persists the resulting events. Actual workflow/activity task types, retries, and history-event details are richer than this teaching-level diagram.

### Step A — Create a scene file

Save as **`src/scenes/temporal-execution.tsx`**:

```tsx
import {Line, makeScene2D, Rect, Txt} from '@motion-canvas/2d';
import {all, createRef, waitFor} from '@motion-canvas/core';

// One lane per participant. All X coordinates are stable.
const lanes = {
  caller: {x: -720, title: 'Caller', color: '#2563eb'},
  server: {x: -240, title: 'Temporal Server', color: '#7c3aed'},
  workflow: {x: 240, title: 'Workflow Worker', color: '#0891b2'},
  activity: {x: 720, title: 'Activity Worker', color: '#059669'},
} as const;

type LaneId = keyof typeof lanes;

type Message = {
  from: LaneId;
  to: LaneId;
  label: string;
  note: string;
  color: string;
};

// Edit this array to change the story without changing drawing code.
const messages: Message[] = [
  {
    from: 'caller',
    to: 'server',
    label: 'StartWorkflowExecution',
    note: 'Server starts the execution and records history events.',
    color: '#60a5fa',
  },
  {
    from: 'workflow',
    to: 'server',
    label: 'PollWorkflowTaskQueue',
    note: 'A workflow worker long-polls its task queue.',
    color: '#22d3ee',
  },
  {
    from: 'server',
    to: 'workflow',
    label: 'Workflow Task',
    note: 'The poll returns a task with workflow history.',
    color: '#a78bfa',
  },
  {
    from: 'workflow',
    to: 'server',
    label: 'ScheduleActivityTask command',
    note: 'Workflow code runs or replays and emits a command.',
    color: '#22d3ee',
  },
  {
    from: 'activity',
    to: 'server',
    label: 'PollActivityTaskQueue',
    note: 'An activity worker long-polls the activity queue.',
    color: '#34d399',
  },
  {
    from: 'server',
    to: 'activity',
    label: 'Activity Task',
    note: 'The server returns an activity task to that poll.',
    color: '#c4b5fd',
  },
  {
    from: 'activity',
    to: 'server',
    label: 'Activity Completed',
    note: 'The result is recorded in workflow history.',
    color: '#34d399',
  },
  {
    from: 'server',
    to: 'workflow',
    label: 'Next Workflow Task',

  },

    label: 'CompleteWorkflowExecution',
    note: 'The worker returns a completion command; the server persists it.',
    color: '#22d3ee',
  },
];

export default makeScene2D(function* (view) {
  view.fill('#0b1220');

  // Title at the top and explanatory caption at the bottom.
  const caption = createRef<Txt>();

  view.add(
    <>
      <Txt
        text={'How Temporal Executes a Workflow'}
        y={-468}
        fontSize={52}
        fontWeight={700}
        fill={'#f8fafc'}
      />
      <Txt
        ref={caption}
        text={'Follow one request through the server and workers.'}
        y={492}
        fontSize={25}
        fill={'#cbd5e1'}
      />
    </>,
  );

  // Create stable participant headers and vertical lifelines.
  for (const lane of Object.values(lanes)) {
    view.add(
      <>
        <Rect
          x={lane.x}
          y={-352}
          width={310}
          height={74}
          radius={14}
          fill={lane.color}
        >
          <Txt text={lane.title} fontSize={28} fill={'#ffffff'} />
        </Rect>
        <Line
          points={[[lane.x, -310], [lane.x, 460]]}
          stroke={'#475569'}
          lineWidth={3}
          lineDash={[9, 10]}
          opacity={0.75}
        />
      </>,
    );
  }

  // A generator helper: draw one arrow, reveal its label, update caption.
  function* animateMessage(message: Message, index: number) {
    const arrow = createRef<Line>();
    const label = createRef<Txt>();

    const fromX = lanes[message.from].x;
    const toX = lanes[message.to].x;
    const y = -260 + index * 83;

    view.add(
      <>
        <Line
          ref={arrow}
          points={[[fromX, y], [toX, y]]}
          stroke={message.color}
          lineWidth={5}
          endArrow
          arrowSize={17}
          end={0}
        />
        <Txt
          ref={label}
          x={(fromX + toX) / 2}
          y={y - 24}
          text={message.label}
          fontSize={21}
          fontWeight={600}
          fill={message.color}
          opacity={0}
        />
      </>,
    );

    yield* all(
      arrow().end(1, 0.7),
      label().opacity(1, 0.35),
      caption().text(message.note, 0.4),
    );

    // Reading time matters: don't rush the diagram.
    yield* waitFor(0.55);
  }

  // The complete story is driven by the messages array.
  for (const [index, message] of messages.entries()) {
    yield* animateMessage(message, index);
  }

  yield* waitFor(1);
});
```

### Modify it yourself

- **Change participants:** edit `lanes`; adjust X coordinates to make room.
- **Change steps:** edit the `messages` array; no drawing logic changes needed.
- **Change pacing:** edit `0.7` for arrow duration and `0.55` for reading time.
- **Change style:** edit the colors, fonts, and stroke widths.
- **Split into multiple scenes:** make one overview and another showing detailed worker replay/history.

> **Design limitation:** This is a fixed 1920×1080-style teaching layout. For a longer sequence, use multiple scenes, scroll/pan with a camera, or implement automated vertical pagination. Do not keep adding messages until they run offscreen.

### Your Temporal batch-workflow storyboard

Use a high-level scene first:

```text
REST/API
   |
   v
Main workflow ----> Coordinator ----> Batch workflow
                         |                  |
                         |              Group by template
                         |              Launch Ansible jobs
                         |              Central polling
                         |                  |
                         <---- signal ------+
   ^                     |
   +------ result -------+
```

Then create focused scenes for:

1. **Batch admission:** enqueue items; deduplicate using workflow ID.
2. **Flush condition:** reach 20 servers or 5 minutes, whichever occurs first.
3. **Routing:** choose Primary/Secondary Ansible and operation/domain/template mapping.
4. **Execution:** launch batches, poll centrally, route terminal results to each parent.
5. **Durability:** signal history, replay, child workflows, Continue-As-New, worker restarts.

That is a **visual storytelling plan**, not an assertion that all those steps happen as independent services in Temporal. Carefully distinguish **workflow code execution**, **Temporal Server task scheduling/persistence**, and **external HTTP calls from activities**.

## 14. Export, common mistakes, and troubleshooting

### Rendering to video or images

In the Motion Canvas editor:

1. Open **Video Settings**.
2. Choose resolution/frame rate and render range.
3. Select **Image sequence** or **Video (FFmpeg)** exporter.
4. Click **Render** and inspect the output directory.

For FFmpeg support in an **existing** project, the official docs describe:

```bash
npm install --save @motion-canvas/ffmpeg
```

And a Vite configuration containing both plugins:

```ts
import {defineConfig} from 'vite';
import motionCanvas from '@motion-canvas/vite-plugin';
import ffmpeg from '@motion-canvas/ffmpeg';

export default defineConfig({
  plugins: [motionCanvas(), ffmpeg()],
});
```

If your scaffold already contains the FFmpeg exporter, don't add it twice. For GIFs, image sequences or rendered videos can be converted with an external tool; Motion Canvas's documented built-in choices are image sequence and the FFmpeg video exporter.

**Sources:** [Rendering](https://motion-canvas.io/docs/rendering/), [Image sequence](https://motion-canvas.io/docs/rendering/image-sequence/), [FFmpeg video](https://motion-canvas.io/docs/rendering/video/).

### Common mistakes — and what they mean

| Problem | Likely cause | Fix |
|---|---|---|
| Scene isn't updating | Missing `?scene` import suffix | Import `./scenes/name?scene` from the project file |
| `Cannot access ... ref` / reference error | Calling `myRef()` before node creation | `view.add(...)` before using the reference |
| `yield*` error | Trying to yield a non-generator | Call a tween with a duration or use a real generator helper |
| Two animations happen one after another | Consecutive `yield*` statements | Wrap them in `yield* all(...)` |
| `sequence` animations overlap unexpectedly | `sequence` staggers **starts**, not completions | Use consecutive `yield*` calls or `chain` |
| Node appears far from expected position | Parent-relative coordinates / canvas origin | Check parent transform and center-based coordinates |
| Elements don't arrange with flex-like layout | Layout not enabled | Add `layout` to the intended layout root |
| Code has no syntax highlighting | Missing grammar/highlighter setup | Configure `Code.defaultHighlighter` and Lezer grammar |
| MP4 isn't an export option | FFmpeg exporter not configured | Add the exporter plugin as documented |
| Imported example from old tutorial fails | Old package path or deprecated `CodeBlock` | Use root package imports and `Code` |
| A scene seems empty during transition | Nodes added after starting transition | Add visible nodes before `yield* slideTransition(...)` |
| Editor preview appears black | Editor viewport shifted / render range wrong | Press `0` to refocus; check timeline play range |
| Windows/WSL file changes not detected | Vite watcher across WSL/Windows filesystem | Keep project files in WSL filesystem if editing via WSL |

### Style tips for impactful system explanations

- **Reveal one cause-and-effect relationship at a time.**
- **Keep lane positions fixed.** Movement should convey meaning, not decoration.
- **Use a stable visual language:** blue = commands, purple = server events, green = completed operations, for example. Document your own convention.
- **Give viewers reading time after each message**; labels alone aren't enough.
- **Treat polling arrows correctly.** Workers poll the server; a task is returned on that poll.
- **Use separate scenes for separate questions:** “Who schedules?” and “How does replay work?” often deserve different diagrams.
- **Only animate what matters.** Excessive spinning and bouncing can make distributed-system explanations less accurate and less legible.

## 15. Learning exercises and official references

### Suggested exercise progression

| Exercise | What you will learn |
|---|---|
| 1. Move a circle, change its color | signals, references, `yield*` |
| 2. Draw a request arrow | `Line`, `endArrow`, `end` |
| 3. Create four participant lifelines | coordinates, basic JSX composition |
| 4. Send five messages in order | generators, sequencing, timing |
| 5. Make labels from data | TypeScript arrays, reusable helpers |
| 6. Add history-event badges | secondary visual channels, visual hierarchy |
| 7. Show server/worker responsibility | focus, storytelling, conceptual accuracy |
| 8. Add a camera and narration cues | camera, `waitUntil`, presentation |
| 9. Render an explanatory MP4 | editor workflow and exporters |
